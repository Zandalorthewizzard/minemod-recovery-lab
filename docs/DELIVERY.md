# Поставка и измерение

## Единица работы

Одна задача — один ограниченный наблюдаемый результат. До начала записываются исходная ревизия, поведение успеха и отказа, разрешённые пути, зависимости, исполнитель, проверяющий, бюджет и условие остановки.

Спецификация описывает поведение, design — устройство, tasks — шаги. OpenSpec хранит договорённости; сам по себе он не обеспечивает изоляцию, таймеры, запуск агентов или PASS.

## Параллелизм

- Только независимые поверхности; пересекающиеся файлы или изменяемый общий контракт требуют последовательной работы.
- Каждый исполнитель получает конкретную базу и один список разрешённых путей. Git-операции и интеграция принадлежат координатору.
- Общие entrypoints/сборочные файлы не выдаются нескольким писателям. Интегратор применяет согласованный патч, а не создаёт продуктовую логику за исполнителей.
- Одна тяжёлая сборка/регрессия одновременно; остальные задачи не запускают дублирующие полные прогоны.
- Ширина шесть использована для независимого чтения в E0, а не как обязательное число кодеров на любую фичу.

## Приёмка и повторы

Проверка относится к точной ревизии. Изменение после зелёной проверки требует повторения затронутых условий. Код написан, сборка прошла, сценарий показан, пользователь принял и релиз опубликован — разные события.

Стартовый предел для небольшой задачи: один ограниченный ремонт после первого отказа; дальнейшее повторение того же класса — остановка и пересмотр постановки, не бесконечный цикл. Доказанный критический риск не скрывается ради лимита. Тайм-аут не превращает незакрытую проверку в PASS.

## Какие часы считаем

1. **Wave wall:** dispatch → завершение всей волны.
2. **Worker intervals:** отдельные интервалы runtime каждого исполнителя; их сумма не равна wall time.
3. **Time to accepted delivery:** начало согласованной задачи → проверенный и принятый пользовательский результат.
4. **Проверки/переделки/ожидание:** отдельные события с причиной; нельзя складывать пересекающиеся интервалы и получать «простой» остаточным вычитанием.

Событие содержит `stage`, `change`, `actor`, `type`, `ts_utc`, источник времени, ревизию/артефакт, попытку и результат. Для нового запуска добавляется измеренная monotonic duration. Историческим событиям монотонные значения не выдумываются. Токены и стоимость публикуются только с согласованной семантикой учёта; отсутствие данных — null, не ноль.

## Честность витрины

Существующая механика и прежние 26/26 не выдаются за новую разработку. E0 демонстрирует только аудит и организацию. Скорость по сравнению с прежними четырьмя часами не объявляется: разные исходное состояние, объём, машина, кэш, модель и полнота журналов.
