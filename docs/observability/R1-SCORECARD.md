## 4. Команды: почему здесь нет phase/exit

`commands.verdict = pending_source`, записей 0. Публичный слой не получал
private command ledgers других worker, а собственный self-test не является их
подменой. Поэтому phase, длительность, attempt и exit code = `null`, а не `0`
и не `PASS`. Коллектор принимает `--commands <jsonl>` и валидирует записи:
отсутствие `exit_code` даёт `incomplete` и вердикт `partial_observation`
(проверено на синтетической фикстуре). Координатору для полного счёта нужно
передать агрегированный ledger в этом формате.

## 5. Результаты задач

На момент снимка в `result_json` присутствовали 2 записи из 6 (`completed`),
остальные ещё не были опубликованы рантаймом. Коллектор фиксирует это как
`task/session count mismatch: 2 task results vs 6 runtime sessions`, а не как
«4 агента провалили». Связка task↔session помечена `session_join:
positional_hypothesis_unverified`.

## 6. Что остаётся неизвестным

- **Runner (роль 01):** состояние сборки/тестов на момент снимка неизвестно — в
  публичном слое нет ни команды, ни exit-кода. `null`, не `PASS` и не «0 тестов».
- **Стоимость и квота:** `cost.usd = null`, `cost_status = unknown`; маршрут
  `opencode-go` не доказывает нулевую цену и не показывает остаток квоты.
- **Токены:** `tokens.billable = null`; счётчики сессий и счётчики задач имеют
  разную семантику и не согласованы.
- **Review/rework:** `review.status = pending`; ни приёмки, ни переделок пока нет.
- **Сопоставление с E0:** см. ниже, `comparison_unknown`.

## 7. E0 — это статический intake, а не новая фича и не новый runtime

E0 зафиксировал волну статического аудита и документации: код не исполнялся,
сборка/GameTest/клиент не запускались, продукт не менялся. Публичные данные —

[e0-events.jsonl](../../metrics/e0-events.jsonl).

| Union интервалов | 576.593 с | 479.300 с |
| Пик worker | 6 | 6 |
| Tools / API | 157 / 151 | 139 / 129 (на снимок) |
| Runtime-проверки | нет (`runtime_checks_performed = false`) | выполняются, результат неизвестен |

Почему это **не** сравнение скорости: у волн разный предмет (статический аудит
против сборки/тестов), разный состав ролей и незавершённый правый столбец.
`comparison_unknown`: сопоставимой контрольной базы автора нет, поэтому
утверждений «быстрее/медленнее» здесь не делается. E0 повторно использует только
разбор фактических Hermes records (`async_delegations`, `sessions`) — тот же
подход, что в private `collect_e0.py`; никакая E0-механика не выдаётся за новую
функцию продукта.
