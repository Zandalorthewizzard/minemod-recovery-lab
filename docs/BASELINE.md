## Что требует следующей ограниченной проверки

1. Воспроизвести baseline на точной ревизии в изолированной среде; сохранить команды, exit codes и полный релевантный вывод.
2. Проверить отрицательный сценарий добычи через реальный непользовательский путь смерти. Существующий тест использует `kill()`: без сверки API нельзя считать его доказательством всех вариантов смерти от окружения.
3. Проверить формат таблицы добычи по фактическому Minecraft 26.3. Сингулярный `condition` — пока вопрос, а не доказанный баг на основании другой версии игры.
4. Проверить клиент, обычный игровой цикл и отсутствие missing assets. Нет дисплея — отдельный статус «не проверено», не PASS.

Каст `(Mob)` в обработчике защищён предикатом `ParryRules`; его не принимаем за доказанный дефект. Точное число тиков замаха также не меняем по приблизительной статической оценке.
