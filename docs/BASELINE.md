Исторические артефакты остаются историческими: R1 их не заменяет и не «улучшает», он даёт независимое подтверждение того же набора сценариев на нашей машине.

## Схема loot-таблицы

Схема (`condition`/`modifier`) **признана валидной**, править JSON не нужно. Ранняя статическая гипотеза о её несовместимости с 26.3 **неверна**: она выросла из нашего же чтения кода и была снята сверкой с метаданными версии. Диспозиция: [`DECISIONS.md`](DECISIONS.md), LAB-08. Граница решения: снят вопрос о формате, а поведенческая проверка добычи остаётся отдельной задачей и R1 её не закрывает. Это рабочий пример правила «статическая гипотеза не идёт в ремонт без проверки».

## Статусы после R1

**Подтверждено нашим прогоном:** сборка, 26/26 серверных GameTest, загрузка данных без ошибок разбора, сборка JAR, старт клиента и принятие `/summon`.

**Только на стенде, не product-level:** атрибуты, фазы, рывок, отражение, парирование в окне, сохранение компонентов щита, добыча при убийстве игроком, правила спавна в пределах тестовой позиции. Стенд не равен живому игроку.

**Не проверено:** установка релизного JAR в лаунчер; естественный спавн в обычном выживании; отрицательная смерть от окружения (лава, падение, другой моб); пиксельный вид сущности, иконки пластины и улучшенного щита.

## Что требует следующей ограниченной проверки

1. Отрицательный сценарий добычи через реальный непользовательский путь смерти. Существующий тест использует `kill()`: без сверки API его нельзя расширять до всех вариантов смерти от окружения. R1 это не закрыл.
2. Клиент глазами: обычный игровой цикл, отсутствие missing assets, вид моба и иконок. Клиентский прогон доказывает загрузку source set и отсутствие краша, но не внешний вид.
3. Живое ощущение парирования: в упор, по телеграфу, с опозданием 1–4 тика.
4. Установка релизного JAR в лаунчер и естественный спавн в выживании.

Пункт «воспроизвести baseline на точной ревизии» **выполнен**: команды, exit codes и вывод зафиксированы в `metrics/r1-*`.

Каст `(Mob)` в обработчике защищён предикатом `ParryRules`; его не принимаем за доказанный дефект. Точное число тиков замаха также не меняем по приблизительной статической оценке.
