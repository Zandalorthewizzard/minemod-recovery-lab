# Решения и диспозиции

## Принятые решения владельца лаборатории

| ID | Решение | Граница |
|---|---|---|
| LAB-01 | Сначала шесть параллельных DeepSeek-инспекторов, исходный экспорт не менять | E0 — статический аудит; без запуска проекта |
| LAB-02 | Постепенно использовать OpenSpec по мере реальной работы | Без массовой конверсии исторических документов |
| LAB-03 | Цель публикации — `Zandalorthewizzard/minemod-recovery-lab` | Source-only intake, сохранить существующий гайд и памятку |
| LAB-04 | Разрешение автора на публичный код и арт подтверждено пользователем | Не является разрешением на новую лицензию |
| LAB-05 | Лицензию не менять без отдельного решения | Сохранено `All-Rights-Reserved` |

## Действующий контракт baseline

- Улучшение оставляет `minecraft:shield`, сохраняет компоненты входа, добавляет `minemod:plated` и принудительный блеск; новый `item_model` рецепт не назначает.
- Текущий клиент — ванильные модели/текстуры плюс тултип. Собственный рендерер щита, авторская геометрия и позы сохранены, но не активированы.
- Парирует защитник-игрок, атакующий Панцирник раскрывается. Противоположная фраза старого чеклиста не переносится в наш слой.
- Прежнее решение отложить арт — исторический baseline, а не автоматический запрет на будущую согласованную задачу лаборатории.

## Что изменилось после сверки отчётов E0

| Находка | Диспозиция координатора |
|---|---|
| «Историю/происхождение S9/S10 нельзя восстановить из bundle» | Неверно в этой общей форме: bundle содержит 12 достижимых коммитов; S9/S10 имеют собственные коммиты. Содержимое current tree подтверждено побайтово |
| «В экспорте нет XML» | Уточнено: есть восемь промежуточных XML, финального XML с 26 тестами нет |
| `(Mob)` в обработчике | Предикат выше проверяет `Mob` и `Enemy`; это хрупкость при будущем рефакторинге, не доказанный текущий баг |
| `condition` в loot table | Нужно доказательство по версии 26.3 и поведенческая проверка, не автоматическая правка под старую схему |
| Отрицательный тест добычи использует `kill()` | Не расширять его значение до всех вариантов смерти от окружения; проверить фактическую семантику пути |
| Спящий рендер/PNG | Технический долг/будущий scope, не вредонос и не уже поставленная визуальная фича |
| План на 240–300 минут из отчёта 06 | Не принят: следующая задача должна быть меньше и согласована отдельно |
| Формула waiting из отчёта 06 | Не принята: пересекающиеся интервалы нельзя вычитать как независимые суммы; нужны явные события блокировки либо объединения интервалов |
| Steering OpenSpec для 06 не доставлен | Решение владельца применяется этим слоем; сырой отчёт 06 не является актуальным планом |
| Процедурный бюджет 30 tool calls | Реально превышен агентами 01 и 04; отражено в scorecard, не скрыто под PASS |

Оригинальные локальные отчёты не переписывались для улучшения картины. Этот документ — результат их сверки, а не новая бесконечная волна ревью.

## Решения R1

Процессные решения, принятые по итогам R1. Не отменяют LAB-01…LAB-05; LAB-08 закрывает открытую строку сверки E0, LAB-11 уточняет границу LAB-05.

| ID | Решение | Причина | Следствия |
|---|---|---|---|
| LAB-06 | Ремонт идёт только по карте наблюдаемых чанков; ремонт «на месте», без карты, не начинается | Авторский опыт: куски «готовы» по отдельности, сквозного результата нет | Карта — входное условие change'а; чанк вне карты не считается ни готовым, ни ремонтируемым; закрытие чанка — наблюдаемым поведением |
| LAB-07 | Измерения берутся из машинных записей (`state.db`, XML, логи), не из самоотчётов агентов; самоотчёт — только гипотеза | Расхождение: агент заявил ~28 мин при фактических 11 | Число без источника не попадает в телеметрию и scorecard; отсутствующее значение — `null`, а не оценка |
| LAB-08 | Схема loot-таблицы `condition`/`modifier` для 26.3 признана валидной по официальным метаданным версии; правка JSON не производится | Статическая гипотеза не подтвердилась замером | Закрывает строку «`condition` в loot table» выше; поведенческая проверка добычи остаётся отдельной задачей |
| LAB-09 | Зелёный тест — проверка сценария на стенде, а не доставленный продукт; в статусах обязательны разные значения: проверено / только в тесте / не подключено / требует проверки | 24/24 зелёных при пустом клиентском `init` | 26/26 не повышает статус того, что стенд не измеряет; смешение статусов в отчёте — дефект отчёта, а не оттенок формулировки |
| LAB-10 | Слой наблюдаемости — один дашборд [`PIPELINE-TELEMETRY.md`](PIPELINE-TELEMETRY.md), воспроизводимый коллектор [`tools/observability/`](../tools/observability) и методология [`docs/observability/`](observability/README.md) | У автора наблюдаемости не было: время эскалаций неизвестно, mtime утрачены, журналы расходятся (6 записей против 10 применений) | Новый замер добавляется в тот же дашборд и коллектор; второй дашборд и второй источник чисел не создаются |
| LAB-11 | Лицензия `All-Rights-Reserved` не меняется; публикация и возврат репозитория правовой режим не меняют | LAB-04 подтверждает право на выкладку кода и арта, но не разрешает новую лицензию | Граница LAB-05 сохранена: публикация и возврат — событие хостинга, а не смена прав |
| LAB-12 | `main` не перезаписывается; приёмка идёт через ветку и PR, слияние — отдельное решение владельца | Кандидат автора был смержен после двух REVISE, ветка оставалась несогласованной 1 ч 39 мин 57 с | Прямой push и force-push в `main` не применяются; у каждого change своя ветка и отдельная запись о слиянии |

LAB-06…LAB-12 — решения о процессе, а не о продукте: раздел «Что не принято» ниже остаётся в силе целиком.

## Что не принято

Ни одна новая игровая фича, изменение контракта щита, миграция стаков, запуск сборки/клиента или релиз. Следующий change находится в статусе предложения.
