# Постепенный OpenSpec

Решение владельца: применять OpenSpec по мере реальной работы, не переписывая весь старый архив.

- `specs/` заполняется согласованными поведенческими контрактами затронутых возможностей.
- `changes/` содержит небольшие предложения и изменения; один change — один ограниченный результат.
- Карта текущего состояния и исторические свидетельства находятся в [docs](../docs/PROJECT-MAP.md), не маскируются под новую полную спецификацию.
- Действующие требования обновляются после проверки и принятия изменения, не по одному факту генерации файлов.
- Оркестрация, бюджет, изоляция, число исправлений и измерения определены отдельно в [DELIVERY](../docs/DELIVERY.md).

Сейчас есть только предложенный change [verify-imported-baseline](changes/verify-imported-baseline/proposal.md). Это проверка существующего поведения, а не новая игровая фича. Полная ретроспективная спецификация не создавалась.

OpenSpec CLI не устанавливался, `init`, `apply`, `archive` и CLI validation не запускались. Пакет Markdown ниже не считается автоматически провалидированным или разрешённым к исполнению.
